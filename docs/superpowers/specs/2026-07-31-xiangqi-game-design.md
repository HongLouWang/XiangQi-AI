# 中国象棋桌面游戏设计规格

## 1. 目标

使用 Python 构建一个带基本图形界面的双人中国象棋游戏。程序采用 PySide6
桌面界面，不接入 AI，但同时提供独立规则引擎、同进程 Python 控制接口以及
仅监听本机的 HTTP/WebSocket 接口，方便以后由机器或 Python 程序控制红方、
黑方或双方。

程序必须支持标准走棋规则、每步终局判断、中国棋规与亚洲棋规的长打裁决、
双方确认和棋、无限悔棋、JSON 与中文纵线记谱的导入导出，以及棋谱回放。
不要求无障碍专项适配。程序必须能在 macOS 上运行，并提供可双击启动的
`.app` 应用包。

## 2. 技术方案

- Python 3.11 或更高版本。
- PySide6 负责桌面图形界面。
- FastAPI 提供 HTTP 接口，原生 WebSocket 端点提供双向事件和命令。
- Pydantic 定义网络协议及棋谱数据模型。
- pytest、pytest-qt 和 FastAPI TestClient 负责自动化测试。
- PyInstaller 生成 macOS `.app` 应用包。

界面、网络和规则引擎必须解耦。规则引擎不得导入 PySide6、FastAPI 或网络
模块，保证它可在无图形环境中独立运行和测试。

代码不得依赖 Windows 或 Linux 专用系统调用。开发和发布验收必须在 macOS
实际完成；应用数据和文件选择使用 Qt 与 Python 的跨平台接口。

## 3. 模块边界

### 3.1 `engine`

维护棋盘、轮次、棋子、合法着法和对局状态。实现车、马、相/象、仕/士、
帅/将、炮、兵/卒的标准规则，包括：

- 蹩马腿、塞象眼、相/象不过河。
- 仕/士和帅/将的九宫限制。
- 炮的隔子吃子规则。
- 兵/卒过河前后走法。
- 将帅不能照面。
- 禁止任何使己方帅/将处于被攻击状态的着法。
- 每一步后判断将军、将死和困毙；困毙方判负。

引擎保留完整、可恢复的状态快照，以支持不限次数的连续悔棋和棋谱回放。

### 3.2 `adjudication`

通过可替换的 `RuleAdjudicator` 接口处理循环局面和长打。开局前可以选择：

- `chinese_2020`：中国象棋协会审定的《象棋竞赛规则（2020版）》。
- `asian_2003`：亚洲象棋联合会 2003 年修订规则。

对局开始后锁定规则模式。JSON 棋谱保存模式和版本，导入时自动恢复。

裁决器记录局面重复、着法性质和责任方，识别长将、长杀、长捉以及组合攻击
着法。达到所选规则的裁决条件时，严格按该规则决定必须变着、判负或和棋：
如果规则要求先变着，则在责任方再次提交违规循环着法时拒绝该步并显示依据；
如果规则要求完成着法后判负，则接受着法后立即结束棋局。

裁决结果包含规则版本、循环起点、相关着法、着法性质、责任方和判罚原因，
供 UI、callback、棋谱和网络接口共同使用。

规则依据：

- 中国象棋竞赛规则（2020版）第六章棋例：
  <https://cnchess.net/rules/rules2020.html>
- 亚洲象棋联合会规则说明及 2003 年修订版入口：
  <https://www.asianxiangqi.org/English/AXFrulesEng.htm>

### 3.3 `notation`

负责完整 JSON 棋谱和中文纵线记谱。

JSON 棋谱保存：

- 格式版本、创建时间、规则模式。
- 玩家姓名、颜色和控制方式。
- 初始局面。
- 每一步的起止坐标、移动棋子、被吃棋子、中文记谱、走后局面摘要、将军状态
  和裁决信息。
- 当前有效着法序列、和棋过程、对局结果与终局原因。

中文棋谱采用标准纵线记谱，例如“炮二平五”和“马８进７”。中文棋谱从标准
初始局面开始重放；每一步都经规则引擎验证。

导入采用事务式流程：先在临时对局中解析并完整重放，全部成功后才替换当前
棋局。错误必须包含文件格式、行号或着法序号，当前对局保持不变。导出先写
同目录临时文件，再原子替换目标文件。

### 3.4 `controller`

`GameController` 是 UI、Python 程序和网络客户端改变棋局的唯一入口。公共
能力包括：

```python
controller.get_state()
controller.get_legal_moves(side=None)
controller.make_move(from_pos, to_pos, actor=None)
controller.undo(steps=1)
controller.offer_draw(actor)
controller.respond_draw(actor, accept)
controller.load_record(path)
controller.export_record(path, format="json")
controller.register_callback(callback)
controller.claim_side(side, controller_id)
controller.release_side(side, controller_id)
```

每次合法着法完成后，控制器按以下顺序执行：

1. 更新局面和棋谱。
2. 检查将军、将死、困毙和所选长打规则。
3. 生成结构化 `GameEvent`。
4. 调用已注册的 Python callback。
5. 向 WebSocket 广播事件。
6. 通知 UI 刷新。

`GameEvent` 至少包含走棋前后局面、着法、下一行动方、是否将军、是否将死、
是否困毙、长打裁决和对局结果。callback 异常只记录错误，不回滚已经完成的
合法着法，也不阻塞其他 callback。

控制器为每个阵营维护控制权。人工 UI、同进程 Python 控制器和网络控制器
可以控制任意一方或双方，但一个阵营同一时间只允许一个外部控制者。用户可
释放外部控制权并切回人工。

### 3.5 `api`

FastAPI 服务默认绑定 `127.0.0.1`，端口可配置，不提供对外网卡绑定选项，
也不要求账号认证。

HTTP 提供状态查询、合法着法、走棋、悔棋、提和、回应和棋、控制权管理及
棋谱导入导出。WebSocket 提供状态事件订阅，并接受带请求 ID 的同类控制
命令。

改变局面的网络命令必须包含：

- 唯一请求 ID。
- 操作者和控制权令牌。
- 客户端预期的局面版本号。

局面版本不匹配时拒绝过期命令。多个观察者可同时连接。网络服务或单个
WebSocket 客户端失败不得终止桌面对局。

## 4. PySide6 界面

棋盘方向固定为红方在下、黑方在上，不根据玩家颜色旋转。棋盘和圆形中文
棋子使用矢量绘制，不依赖外部图片，并随窗口清晰缩放。

主窗口布局：

- 中央：棋盘。
- 左侧：玩家 1、玩家 2 的姓名、红黑方分配和人工/Python/网络控制方式。
- 右侧：中文着法列表、当前行动方、规则模式、将军提示和终局原因。
- 底部：新局、悔棋、提和、回应和棋、导入、导出和回放控制。

玩家 1 和玩家 2 可以在新局对话框中互换红黑方，但不能选择同一颜色。

### 4.1 棋盘交互和高亮

- 左键单击当前可走方的棋子后，该棋子进入选中高亮。
- 同时显示该棋子的全部合法落点。
- 再次单击该棋子或单击无操作含义的棋盘空白处，取消选择和落点提示。
- 单击合法落点完成走棋。
- 完成走棋后清除选择态，但最后一步的起点和终点持续高亮。
- 对方走棋后，其刚移动的棋子保持最后着高亮，直到下一步完成。
- 选中棋子与最后着使用不同颜色，两种高亮可以同时存在。
- 悔棋和回放时，最后着高亮随当前局面或回放游标更新。

### 4.2 和棋

任一方可以提出和棋。另一方必须明确同意或拒绝；只有同意后棋局才以和棋
结束。拒绝后继续对局。存在待回应提和时，不能由发起方自行确认。

### 4.3 悔棋

- 悔棋次数不限，可一次撤回多步，直至开局。
- 终局后仍可悔棋并恢复进行。
- 悔棋撤销尚未完成的提和状态。
- 恢复完整局面、行动方、吃子、裁决状态和最后着高亮。
- 导入棋谱后同样可以悔棋。
- 外部控制某方时，人工 UI 仍可悔棋，API 也可请求悔棋。
- 悔棋后再走会截断原有效着法序列。

### 4.4 回放

回放提供首步、上一步、播放/暂停、下一步、末步和播放速度。回放期间禁止
正常落子，只移动回放游标且不改写原棋谱。用户选择“从此继续”后，程序截断
游标之后的着法，退出回放并开始新的对局分支。

## 5. 对局状态和终局

对局状态包括进行中、等待和棋回应、将死、困毙、长打裁决结束及双方同意
和棋。完成每一步合法棋后必须立即运行终局检测并更新 callback、WebSocket
和 UI。

终局后棋盘保持可查看，允许导出、回放和悔棋，不允许继续走棋，除非先悔棋
恢复进行或从历史局面创建分支。

## 6. 错误处理与生命周期

- 非法走棋返回结构化原因，棋盘、回合和棋谱不变。
- 导入失败不替换当前棋局。
- 导出失败不破坏已有目标文件。
- callback 异常被隔离并记录。
- 网络故障不终止桌面棋局。
- 关闭主窗口时停止回放计时器并正常关闭本机 API 服务。

## 7. 测试与验收

### 7.1 规则测试

覆盖所有棋子走法、边界、蹩马腿、塞象眼、炮架、兵卒过河、九宫、将帅
照面、自陷将军、吃子、将军、将死和困毙。

### 7.2 棋例测试

为中国棋规和亚洲棋规分别建立固定局面与着法序列，覆盖长将、长杀、
长捉/长打、组合攻击、单方责任、双方责任、必须变着、判负、和棋及允许
重复。测试必须验证裁决依据、循环起点和责任方，而不只验证最终胜负。

### 7.3 控制器与棋谱测试

覆盖不限次数悔棋、终局后悔棋、提和同意/拒绝、callback 隔离、控制权、
JSON 无损往返、中文棋谱解析、非法导入回滚、回放和从历史局面分支。

### 7.4 API 和 UI 测试

覆盖 HTTP/WebSocket 命令、过期版本拒绝、请求 ID、控制权冲突、棋子左键
选择、合法落点、最后着持续高亮、对方棋子高亮、回放按钮及文件操作。

### 7.5 人工验收

在 macOS 的实际 PySide6 窗口中完成：

1. 配置玩家与规则模式并开始新局。
2. 选中棋子，检查合法落点和最后着高亮。
3. 走棋并连续悔棋。
4. 提和并分别验证拒绝与同意。
5. 分别导出和导入 JSON 与中文棋谱。
6. 完成回放并从中间局面继续。
7. 通过 Python API 和本机网络 API 分别控制红方或黑方。
8. 构建 `.app`，从 Finder 双击启动并完成一次走棋和退出。

所有自动化测试通过且上述人工流程无阻断问题，才视为达到交付标准。
