# 中国象棋 AlphaZero 训练系统设计

## 目标

在 `src/ai/` 中实现一套可在个人计算机上运行的轻量 AlphaZero 中国象棋训练系统。系统复用现有 `xiangqi` 规则引擎，通过 Policy/Value 神经网络、蒙特卡洛树搜索（MCTS）与自我对弈，从随机初始化开始迭代训练，不依赖人工棋谱或手工局面评分。

默认训练目标为 10,000 局，可通过 Python 配置对象或命令行参数修改。每盘最多 512 个完整回合，即红黑双方最多各走 512 步、总计 1024 ply；仍未终局时按和棋处理，训练价值目标为 0。

## 范围

第一版包含：

- 中国象棋局面和合法动作的神经网络编码。
- Policy/Value ResNet。
- PUCT MCTS。
- 自我对弈、Replay Buffer 与训练循环。
- CPU、多进程 CPU、CUDA GPU 三种运行方式。
- 暂停、恢复、断点续传及追加训练局数。
- 命令行入口、Python API、状态文件、检查点与自动化测试。

第一版不包含 GAN、大师棋谱监督学习、分布式多机训练、图形训练面板或云端调度。GAN 不属于 DeepMind AlphaZero 的核心棋力路线，后续如需生成特殊局面，可通过独立数据生产接口扩展。

## 总体架构

```text
现有 xiangqi 规则引擎
          ↓
棋盘与历史特征编码
          ↓
Policy/Value ResNet ←─────────────┐
          ↓                       │
       PUCT MCTS                  │
          ↓                       │
       自我对弈                    │
          ↓                       │
 (state, policy, value)           │
          ↓                       │
     Replay Buffer                │
          ↓                       │
      梯度训练 ── checkpoint ──────┘
```

系统拆分为配置、编码、模型、搜索、自我对弈、数据存储、检查点和训练协调八个边界清晰的模块。规则合法性和终局判定始终由现有 `xiangqi` 包负责，AI 层不复制棋规。

## 文件结构

计划在 `src/ai/` 下建立 Python 包：

- `config.py`：强类型训练、网络、MCTS、设备和存储配置。
- `encoding.py`：棋盘特征、动作空间及对称视角转换。
- `network.py`：Policy/Value ResNet 与设备选择。
- `mcts.py`：PUCT 搜索树、根节点噪声和访问次数策略。
- `self_play.py`：单盘对弈、1024 ply 截止和训练样本回填。
- `replay.py`：有容量上限的磁盘 Replay Buffer。
- `checkpoint.py`：原子保存、加载与兼容性校验。
- `trainer.py`：自我对弈、优化、评估和保存的迭代协调。
- `control.py`：暂停请求、状态查询和追加目标局数。
- `cli.py`、`__main__.py`：命令行入口。

测试放在 `tests/ai/`，按模块对应组织。

## 局面与动作编码

棋盘采用当前行棋方视角编码，使同一网络可服务红黑双方。输入至少包含：

- 当前方 7 种棋子的 7 个二值平面。
- 对方 7 种棋子的 7 个二值平面。
- 当前行棋方平面。
- 最近若干历史局面的重复/历史特征平面。

张量形状固定为 `[channels, 10, 9]`。红方和黑方使用统一朝向，黑方视角进行棋盘旋转及颜色交换。

动作空间使用确定性的“起点格 × 终点格”编码，共 `90 × 90 = 8100` 个槽位。网络输出完整 logits；MCTS 在每个局面只对现有规则引擎返回的合法动作做掩码和归一化。虽然动作空间包含不可能动作，但编码简单、可逆且不会因走法规则扩展而改变检查点格式。

## 神经网络

模型采用适合 10×9 棋盘的小型 ResNet：

- 输入卷积和批归一化。
- 可配置数量和宽度的残差块。
- Policy 头输出 8100 个动作 logits。
- Value 头输出 `[-1, 1]` 标量，表示当前行棋方最终胜负预期。

默认网络以个人设备可运行优先，不宣称在 10,000 局后达到专业棋力。网络宽度和残差块数量均可配置，检查点保存完整配置以防不兼容模型被误载。

## MCTS 与自我对弈

MCTS 使用 PUCT：

- 神经网络提供叶节点先验概率与价值。
- 选择分数结合平均价值、先验概率和访问次数。
- 根节点在训练时加入 Dirichlet 噪声以鼓励探索。
- 开局阶段按访问次数和温度采样，之后选择访问次数最高的动作。
- 推理期间不加入根噪声，可使用确定性动作。

每一步保存当前视角的局面张量和 MCTS 归一化访问概率。棋局结束后，将最终胜负从各样本的当前行棋方视角回填为 `+1`、`0` 或 `-1`。

终止顺序为：

1. 现有规则引擎判定将死、困毙或棋规终局。
2. 已执行 1024 ply 时强制和棋。
3. 否则继续搜索。

“512 个完整回合”是默认配置，程序内部以 `max_plies=1024` 表达；用户可以通过配置修改，但命令行帮助同时显示完整回合数与 ply，避免歧义。

## 训练循环与默认规模

默认 `target_games=10000`。协调器重复执行：

1. 使用当前模型产生自我对弈棋局。
2. 将完整棋局的样本原子追加到 Replay Buffer。
3. 当样本量满足最小批次后随机采样并执行梯度更新。
4. 定期保存检查点和可读状态。
5. 达到目标总局数后保存最终检查点并正常退出。

目标局数是累计目标，不是每次启动额外再跑 10,000 局。例如检查点已完成 3,000 局且目标为 10,000 局，恢复后继续 7,000 局。追加 5,000 局会把累计目标改为 15,000 局。

## CPU 与 CUDA

设备配置支持：

- `auto`：CUDA 可用时选择 CUDA，否则选择 CPU。
- `cpu`：强制 CPU。
- `cuda` 或 `cuda:N`：强制指定 CUDA 设备；不可用时明确报错，不静默回退。

CPU 训练支持两个独立参数：

- `torch_threads`：PyTorch 算子线程数，通过 `torch.set_num_threads` 设置。
- `self_play_workers`：并行自我对弈工作进程数。

CUDA 模式下，网络训练和批量推理使用指定 GPU；自我对弈调度仍可使用多个 CPU 工作进程。为避免多个进程各自抢占整张显卡，第一版由主进程持有 CUDA 模型并提供批量推理，工作进程负责规则推进和搜索任务。若无法满足跨进程批量调度，则先以单个 CUDA 自我对弈协调器保证正确性，同时保留配置校验，不能伪称多进程 GPU 推理已启用。

测试环境没有 CUDA 时，使用依赖注入验证设备选择与错误分支；CUDA 张量运算只在真实 CUDA 可用时执行并标记条件跳过。

## Replay Buffer

Replay Buffer 是有容量上限的持久化数据集：

- 以完整棋局为提交单位，避免恢复后出现半盘样本。
- 样本使用紧凑数组格式存储，策略只持久化合法动作的稀疏概率。
- 保存格式包含 schema 版本、动作空间版本和编码版本。
- 超过容量时从最旧棋局开始淘汰。
- 检查点只保存 Replay Buffer 清单和游标，不重复嵌入全部训练数据。

训练状态目录允许用户指定，默认位于项目下的 `AI-runs/default/`；运行产物加入 `.gitignore`，不会提交模型或海量自我对弈数据。

## 暂停、恢复、断点续传与追加

训练目录包含一个协调状态文件和控制请求文件。控制命令包括：

- `train`：新建训练；目录已有兼容检查点时默认续传。
- `pause`：写入暂停请求。
- `resume`：清除暂停状态并从最近检查点继续。
- `extend --games N`：在当前累计目标上追加 N 局。
- `status`：读取当前局数、目标、训练步数、设备、状态和最近检查点。

暂停是协作式安全暂停：协调器完成当前最小原子工作单元，落盘 Replay Buffer、模型、优化器和状态后进入 `paused`，不会在写文件中途强杀进程。

检查点至少包含：

- 模型与优化器状态。
- 学习率调度器状态（启用时）。
- 已完成局数、目标局数和训练步数。
- 完整配置与格式版本。
- Replay Buffer 清单/游标。
- Python、NumPy、PyTorch CPU 和 CUDA 随机数状态。

所有关键文件先写同目录临时文件，刷新后用原子替换发布。加载时验证格式版本、配置兼容性和校验信息；损坏的最新检查点不会覆盖上一份可用检查点。

## 命令行与 Python API

预期命令示例：

```bash
python -m ai train --run-dir AI-runs/default
python -m ai train --games 20000 --device cpu --self-play-workers 8 --torch-threads 8
python -m ai train --device cuda:0
python -m ai pause --run-dir AI-runs/default
python -m ai resume --run-dir AI-runs/default
python -m ai extend --run-dir AI-runs/default --games 5000
python -m ai status --run-dir AI-runs/default
```

Python 调用通过不可变配置对象修改默认值：

```python
from ai.config import TrainingConfig
from ai.trainer import Trainer

config = TrainingConfig(target_games=20_000, max_full_moves=512)
Trainer(config).run()
```

配置同时接受 `max_full_moves`，内部派生并验证 `max_plies == max_full_moves * 2`，不允许两者矛盾。

## 错误处理

- CUDA 被显式请求但不可用：启动前失败并给出设备诊断。
- 检查点架构或编码版本不兼容：拒绝加载并保留现有文件。
- 单盘工作进程异常：记录棋局编号和 traceback；不提交半盘数据。可配置有限次数重试，超过阈值后安全保存并退出。
- 磁盘写入失败：停止生成新任务，保留上一原子检查点并以非零状态退出。
- 无合法走法：交由现有规则引擎确定胜负，不由 AI 猜测。
- 非法网络动作：合法动作掩码保证不会选择；若仍发生则视为内部错误并停止该棋局。

## 测试与验收

实现采用测试先行。至少覆盖：

- 红黑视角编码一致性和动作编解码双向可逆。
- Policy 合法动作掩码和 Value 输出范围。
- PUCT 选择、价值符号反传、根噪声与温度策略。
- 自我对弈在真实终局正确回填标签。
- 第 1024 ply 后强制和棋，且不会产生第 1025 ply。
- 默认目标恰为 10,000 局，Python 和命令行均可覆盖。
- CPU 的 `torch_threads` 与 `self_play_workers` 被正确应用。
- `auto`、`cpu`、`cuda`、`cuda:N` 的选择和失败行为。
- 暂停只在安全点完成，并产生可加载检查点。
- 从检查点恢复后局数、训练步数、优化器和随机状态连续。
- 追加局数按累计目标增加，不重置已完成局数。
- 损坏或不兼容检查点被拒绝，上一可用检查点仍可恢复。

验收时运行完整现有测试，确保 AI 可选依赖没有破坏桌面程序；另外运行 AI 单元测试、短程 CPU 烟雾训练、暂停/恢复/追加集成测试。真实 CUDA 可用时再运行 CUDA 烟雾训练，并报告当前机器是否具备该验证条件。

## 成功标准

系统满足以下条件才算完成：

1. 可从随机模型运行完整的 Policy/Value + MCTS 自我对弈训练循环。
2. 默认累计目标为 10,000 局，并可从程序和命令行修改。
3. 单盘上限为 512 个完整回合（1024 ply），上限局按和棋训练。
4. CPU 训练可设置 PyTorch 线程数和自我对弈工作进程数。
5. GPU 训练支持显式 CUDA 设备并在不可用时可靠报错。
6. 训练可以安全暂停、恢复、断点续传和追加目标局数。
7. 所有持久化写入具备崩溃安全边界，自动化测试和可执行烟雾测试通过。
